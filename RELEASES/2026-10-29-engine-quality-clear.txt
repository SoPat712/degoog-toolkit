Engine Quality Dashboard: clear history — 2026-10-29
===================================================
Channel: develop. Dashboard version 1.0.1 -> 1.1.0.

The dashboard header now includes Clear history beside Refresh and Download
JSON. It uses the existing admin session and asks for confirmation before
clearing all saved engine statistics, for every search type and period,
regardless of the active filters. Recording continues when enabled. Engine,
timeout, transport, collection and retention settings are unchanged.

The same-origin, rate-limited POST clear route requires JSON with an exact
confirmation marker. Authorization runs before history access. Missing/expired
sessions and cross-site requests are denied; protected responses are private
and no-store. Clearing an unsafe or unopened history store is rejected.

Clear waits for a pending save, writes an empty generation using the shared
atomic writer, then resets in-memory aggregates, recording-start timestamp and
dropped-report count. A failed write preserves the previous history in memory
and on disk and reports failure. Records arriving before clear completes are
within the reset's scope; subsequent records persist normally. UI polling and
in-flight reads cannot restore pre-clear data during the operation. A failed
clear keeps the current dashboard data visible with an error message.

Confirmation, progress, success and failure text is included in all nine
dashboard languages. The clear control remains disabled until authorized data
loads, while a clear is in progress, or if storage could not be opened safely.
Download JSON remains available as an optional copy before clearing.
