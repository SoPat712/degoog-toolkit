Changes
-------
Dictionary adds an explicit Wiktionary definition source, English meaning and
example normalization, source/license attribution, separate source caches and
visible definition failures. Free Dictionary API remains the distributed
default and the backend for dedicated pronunciation/origin requests. The
operator selected Wiktionary on the tested deployment after the original
provider returned HTTP 403 to one client and timed out with the plugin's client.
The actual search URL for "define cosmopolitan" now renders three definitions;
"define serendipity" also passed. Synonyms do not replace missing meanings.

Mwmbl adds an explicit native-index mode, v2 query-parameter compatibility and
typed provider/parsing failures. API mode remains the distributed default.
Native mode omits the API's live Wikipedia enrichment and can return fewer
results; it is an explicit choice rather than a silent fallback.

NeoSearch adds rendered-page support for 4play, explicit API/browser selection,
region handling and detection of provider errors/unready pages. Both modes
retain the configured engine deadline. The provider's daily quota still applies.

Food Facts is a new toolkit engine using Open Food Facts full-text search with
projected fields, pagination and product/brand/Nutri-Score result metadata.
The tested deployment enabled it and disabled Devinside's overlapping engine
through operator settings. Devinside's source was not changed.

SearXNG Videos includes separate optional Vimeo, YouTube and Brave modules.
Vimeo/YouTube reduce payloads while reusing upstream parsing and pagination.
Brave handles literal function-wrapped hydration data without executing provider
JavaScript, then delegates video mapping to the official parser. These modules
require installation on the SearXNG host; a Store update alone cannot mount them.
See engines/searxng-videos/searxng/INSTALL.txt for installation and rollback.

Both themes show image titles/sources before lazy thumbnails finish loading.
LiterallyGoogle also owns its home settings SVG and rotates it around a fixed
center without the previous hover offset.

Observed limits and upstream follow-up
-------------------------------------
These are individual actual-search-URL observations, not latency guarantees:
  Mwmbl: 10 results / 340 ms on the original problem query; intermittent native
    timeouts remain, and narrow queries can genuinely have fewer than 10 hits.
  Aggregate videos: 106 results / 820 ms and 147 results / 1,740 ms. Brave's
    repaired parser restored 50 results. Vimeo still has upstream network tails.
  Findfiles: 15 results / 1,476 ms, with other successes taking 2,004–2,891 ms.
    Its repair involved operator DNS/transport settings, not a new toolkit engine.

Potential upstream fixes: Brave's old hydration extractor rejects valid current
provider data; the degoog bang UI can present a backend failure as ordinary
"No results"; Mwmbl enrichment and intermittent native latency need provider-side
investigation. No official source patch or upstream PR is included here.

No deadline was raised to manufacture a passing result, no result count was
padded and failing providers were not disabled to hide aggregate failures.
Selecting official 4play for Findfiles does invoke degoog's transport-derived
effective deadline; that separate behavior is disclosed in the private audit.
The sub-1,500 ms / minimum-10 goal is not universally achieved.

Follow-up — Videos reliability and repository cleanup
====================================================
Store updates: SearXNG Videos 1.5.1; Food Facts 1.0.1 (owner's replacement
screenshot, preserved without editing). No new Mwmbl version or timeout change.

The Videos connector previously accepted a missing/malformed results array as
successful zero results. It also discarded unresponsive_engines when SearXNG
returned HTTP 200 with no results and failed providers. The connector now reports
those conditions as failures, validates unusable result sets, checks HTTP errors
even with an observing sentinel, and preserves cancellation on truncated bodies.
Valid partial results remain intact, with provider failures logged without the
query. The current degoog result-array contract has no partial-warning field for
its success row; this remaining UI limitation is an upstream enhancement request.

Deployed only the owned Videos index.js, with a private prior-file backup and one
degoog restart. No engine settings changed. Live public metadata retained all four
custom settings fields. The real Bun candidate returned 155 results / 2,174 ms;
the subsequent normal URL returned 154 SearXNG results / 1,311 ms:
  https://dg.joshpatra.me/search?q=flower+arrangement+tutorial&type=videos
The entire page took 2.92 s because the separate official Google Videos engine
took 2,886 ms. That is not the SearXNG connector's latency. Its Google/Qwant
provider failures remain explicitly recorded in the server log.

Additional real URL observations (page-reported timings, not cold-cache claims):
  !mw nginx upstream load balancing: 10 results / 320 ms.
  !mw python asyncio queues: 81 results / 370 ms.
  !mw SQLite: 44 results / 400 ms.
  !mw sqlite wal checkpoint busy readers: 4 results / 140 ms.
  !sxv hand cut dovetail tutorial: 123 results / 850 ms.
  !sxv watercolor landscape painting: 152 results / 1,400 ms.
Twelve additional low-rate direct Mwmbl probes reproduced no timeout. They do not
establish that the intermittent failure is solved. Native-index coverage still
limits narrow queries; no results were padded or queries broadened in the engine.

Vimeo investigation and rejected settings trial
----------------------------------------------
Two aggregate traces spent 2,744–2,946 ms loading Vimeo's response, with roughly
25 ms of local processing. A counterbalanced comparison of compact /videos and
/search responses gave no consistent route gain. They returned 20 pottery videos
on both routes and 19 watercolor videos, with one differing ranked URL.

A direct protocol comparison suggested HTTP/1.1 might help, so only Vimeo's
enable_http2 setting was temporarily set false. Actual SearXNG-only observations:
  HTTP/2: 1,232; 1,484; 877; 857 ms.
  HTTP/1.1: 1,427; 1,051; 1,174; 957 ms.
The normal Videos UI retry also worsened from 1,009 to 1,228 ms. The trial was
rejected and the exact previous YAML restored, verified by its SHA256. The
installed container image, result limits and every timeout stayed unchanged.
Vimeo response tails remain a provider/network investigation, not a claimed fix.

Upstream references for further work:

  https://github.com/mwmbl/mwmbl/blob/main/mwmbl/views.py
  SearXNG's Vimeo authentication/parser contract:
  https://github.com/searxng/searxng/blob/master/searx/engines/vimeo.py
  Existing degoog bang failure-display issue: a timed-out engine can appear as

  narrows its type without status/error; :355 renders timings only for media,
  and :357 renders the empty results. src/client/modules/renderer/render.ts:122
  selects the generic No results message. An upstream fix should preserve the
  timing's status/error and render the failure/retry state for web bangs too.
  These are reference locations for a future PR; official code was not edited.
