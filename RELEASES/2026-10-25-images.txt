Initial SearXNG connector change (superseded by follow-up below)
--------------------------------------------------------------
The initial 1.3.13 Images connector sent SearXNG's supported timeout_limit when
an explicit degoog timeout was configured. It reserved min(200 ms, 10% of the
deadline) for transmission and parsing: 3000 ms requests 2.8 seconds of collection.
This prevents SearXNG from spending the whole parent deadline collecting results
and losing completed provider results when degoog cancels the response.

This bounds collection time; it does not repair or accelerate a failing provider.
Unresponsive providers remain in SearXNG diagnostics. The connector validates
payloads, rejects unusable/empty failed responses, preserves cancellation, and
logs failed providers when retaining valid partial results. Logs omit the query.
Core's successful-result contract cannot carry those warnings into the engine
performance row, so partial-provider failures remain in the server log.

Important upstream deadline exception
------------------------------------
Google Images has a saved 3000 ms engine setting, but its working official
4play transport has a 15000 ms transport timeout. Official degoog's
src/server/search/engine-timeout.ts increases an engine deadline to the longer
transport timeout plus ENGINE_TIMEOUT_BUFFER_MS (5000). Its effective ceiling
therefore remains 20000 ms. This upstream behavior overrides an explicit engine
limit. It needs a core fix to honor the engine deadline/cancellation independently
of transport defaults. No official code was patched here.

Direct Fetch and Curl returned zero usable Google images in the tested current
format, and Curl Impersonate received a JavaScript/consent interstitial. The
working 4play transport was retained. Its shared timeout was not lowered because
that would also change unrelated non-image engines. Do not claim every effective
engine deadline is 3000 ms, or that every image provider meets 1500 ms.

Follow-up — keep timeout policy in settings
==========================================
The operator clarified that the connector must not derive an additional inner
deadline. SearXNG Images 1.3.14 removes the automatic timeout_limit query
parameter, the fixed 200 ms reserve, and the private timeoutMs configuration
state. No replacement timer, reserve or collection limit was added. Degoog's
normal Timeout (ms) setting and cancellation still control the outer request;
SearXNG's provider deadlines remain operator-controlled server settings.

The actual reliability changes from 1.3.13 remain: explicit HTTP error status,
validation of malformed/unusable result payloads, errors for empty responses
with upstream failures, partial-result failure logging without queries, correct
parent-cancellation handling, and the server-only network declaration.

Verified through the real search URL after deploying the correction:
  https://dg.joshpatra.me/search?q=autumn+forest&type=images
  SearXNG Images: 0 results / 3052 ms, explicitly "Timed out"
